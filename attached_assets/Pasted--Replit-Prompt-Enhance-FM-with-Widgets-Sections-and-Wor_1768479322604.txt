# Replit Prompt: Enhance FM with Widgets, Sections, and Work Item Improvements

## Context

I have an existing Feature Management (FM) module in the `fm` schema with these tables:
- `fm.page_requirements` - Pages/screens with routes
- `fm.work_items` - Epics, FRs, ACs, Bugs, Tasks, TestCases (discriminated by `type` column)
- `fm.work_item_links` - Relationships between work items
- `fm.data_models` - Domain objects with field definitions
- `fm.change_log` - Change history
- `fm.test_runs` / `fm.test_run_results` - Test execution tracking

---

## PART 1: Schema Changes

### 1.1 Create fm.apps table

Multi-app support (GameScope, MAGPIE, etc.):

```sql
CREATE TABLE fm.apps (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  framework TEXT,              -- 'react', 'angular'
  status TEXT DEFAULT 'active',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Seed with initial apps
INSERT INTO fm.apps (id, name, description, framework) VALUES
  ('gamescope', 'GameScope', 'Team management and video analysis platform', 'react'),
  ('magpie', 'MAGPIE', 'Player recruitment and scouting platform', 'react');
```

### 1.2 Create fm.widgets table

Reusable UI components:

```sql
CREATE TABLE fm.widgets (
  id TEXT PRIMARY KEY,
  app_id TEXT REFERENCES fm.apps(id),
  name TEXT NOT NULL,
  description TEXT,
  data_models JSONB,           -- Array of data model IDs this widget consumes
  config_schema JSONB,         -- Optional: JSON schema for widget configuration
  status TEXT DEFAULT 'active',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 1.3 Add columns to fm.work_items

New columns for linking, sections, and tracking:

```sql
ALTER TABLE fm.work_items 
  ADD COLUMN created_by TEXT,
  ADD COLUMN assigned_to TEXT,
  ADD COLUMN priority_rank INTEGER,    -- 1 to 5 for ordering
  ADD COLUMN size TEXT,                -- 'S', 'M', 'L', 'XL'
  ADD COLUMN effort INTEGER,           -- 0 to 99
  ADD COLUMN app_id TEXT REFERENCES fm.apps(id),
  ADD COLUMN page_id TEXT REFERENCES fm.page_requirements(id),
  ADD COLUMN widget_id TEXT REFERENCES fm.widgets(id),
  ADD COLUMN section_title TEXT,
  ADD COLUMN section_order INTEGER,
  ADD COLUMN section_type TEXT;        -- 'section', 'modal', 'tab', 'drawer', 'dropdown', 'nested-tab'
```

**section_type values:**

| Type | Description | section_order |
|------|-------------|---------------|
| `section` | Main content area on page | Required (0, 1, 2...) |
| `tab` | Tab within a tab bar | Required (order within tabs) |
| `nested-tab` | Sub-tab within a parent tab | Required (order within parent) |
| `modal` | Dialog/popup overlay | NULL (not positioned) |
| `drawer` | Slide-out panel | NULL |
| `dropdown` | Menu content | NULL |

### 1.4 Add app_id to existing tables

```sql
ALTER TABLE fm.page_requirements ADD COLUMN app_id TEXT REFERENCES fm.apps(id);
ALTER TABLE fm.data_models ADD COLUMN app_id TEXT REFERENCES fm.apps(id);
```

### 1.5 Data Migration

```sql
-- Normalize status to lowercase
UPDATE fm.work_items SET status = lower(status) WHERE status IS NOT NULL;

-- Set all existing records to GameScope app
UPDATE fm.work_items SET app_id = 'gamescope' WHERE app_id IS NULL;
UPDATE fm.page_requirements SET app_id = 'gamescope' WHERE app_id IS NULL;
UPDATE fm.data_models SET app_id = 'gamescope' WHERE app_id IS NULL;
```

Use consistent status values across all work item types:

| Status | Description |
|--------|-------------|
| `new` | Just created, not yet detailed |
| `defined` | Fully specified/understood |
| `in_progress` | Being worked on |
| `qc` | Ready for testing/verification |
| `complete` | Done/Released |

These apply to: Epic, FR, AC, Bug, Enhancement, Task, TestCase

## PART 3: UI Updates

### 3.1 Add App Selector

Add an app selector dropdown to the FM header:
- Pulls from `fm.apps` table
- Filters all FM views to show only items for selected app
- Persists selection in localStorage
- Default to 'gamescope' if not set

### 3.2 Add Widgets Tab

Add a "Widgets" tab to Feature Management alongside List, Epics, Objects, Screens.

**Widget List View (left panel):**
- List of widgets showing: name, usage count (count of ACs with this widget_id)
- "+ New Widget" button
- Click to select and show detail

**Widget Detail View (right panel):**
- Widget name (editable)
- Description (editable textarea)
- Data Models consumed (multi-select dropdown from fm.data_models)
- **Used By section:** List of ACs that reference this widget, grouped by page

**Add/Edit Widget Dialog:**
- Name (required, text input)
- Description (textarea)
- Data Models (multi-select from fm.data_models)
- App (dropdown from fm.apps, default to current app context)

### 3.3 Update Screens Tab

The Screens tab currently shows 4 columns: Widgets | Pages | Sections | Stories

**Column 1 - Widgets:**
- Pulls from `fm.widgets` table
- Shows widget name and usage count
- Click to filter Pages to those using this widget

**Column 2 - Pages:**
- Unchanged - pulls from `fm.page_requirements`
- When selected, Sections column updates

**Column 3 - Sections:**
- Shows ACs for selected page that have `section_title` populated
- Sorted by `section_order`
- Display format: `{section_order}: {section_title}`
- Shows linked widget name if `widget_id` is set

**Column 4 - Stories:**
- Shows AC detail when section is selected

### 3.4 Update Work Item Edit Forms

#### For all work item types, add these fields:

**Assignment & Tracking section:**
- Created By (text, auto-fill current user on create)
- Assigned To (text)
- Status (dropdown: new, defined, in_progress, qc, complete)

**Estimation section (collapsible):**
- Priority (dropdown: low, medium, high, critical) - already exists, ensure it's editable
- Priority Rank (number input 1-5)
- Size (dropdown: S, M, L, XL)
- Effort (number input 0-99)

#### For AC (Acceptance Criteria), add Section Info panel:

**Section Info (collapsible):**
- Section Title (text input) - Display name on the page
- Section Order (number input) - Order on page (0, 1, 2...) - leave NULL for modals/drawers
- Section Type (dropdown: section, tab, nested-tab, modal, drawer, dropdown)
- Widget (searchable dropdown from fm.widgets)

#### For TestCase, ensure these fields are editable:

- Title (text)
- Objective (textarea) → maps to `description` field
- Steps (textarea, one step per line - UI displays with numbers)
- Expected Result (textarea)
- Area/Component (dropdown)
- Linked ACs (multi-select, creates work_item_links with type 'traces_to')

### 3.5 Update Epic Detail View

When viewing an Epic and its child FRs/ACs, if ACs have section info, display hierarchically:

```
Epic: Personal Landing Pages
└── FR-001: Personal Landing Page
    ├── 0: Configure → Widget Configurator
```

Format: `{section_order}: {section_title} → {widget.name}`

ACs without section info display normally (just title).

### 3.6 Add Test Case UI

**Add Test Case button** (in Issues or dedicated Testing section):

Opens dialog with:
- Title (text, required)
- Objective (textarea) → stored in `description`
- Steps (textarea, one step per line) → stored in `steps` as TEXT
- Expected Result (textarea) → stored in `expected_result`
- Area (dropdown: HOME, TEAM, CLUB, DEVOPS)
- Priority (dropdown)
- Linked ACs (multi-select from ACs) → creates work_item_links

**Steps display:** When showing steps, split by newline and prepend numbers:
```

Click on Clubs
Click Add Club"

Display:
1. Login to GameScope
2. Click on Clubs
3. Click Add Club
```

### 3.7 Add Test Execution UI

**On Test Case detail view, add "Record Result" button:**

Opens dialog:
- Outcome (dropdown: passed, failed, blocked, skipped)
- Actual Result (textarea)
- Tester (text, auto-fill current user)
- Date (date picker, auto-fill today)

On save:
- Creates record in `fm.test_run_results`
- If no active test run, create one automatically or prompt to select/create

**Quick execution mode (optional enhancement):**
- Button to start a test run
- Shows test cases one by one
- Record pass/fail quickly
- Auto-advances to next test case

### 3.8 Link Bug to Test Case

**When creating a Bug from a failed test:**
- Pre-fill Area from test case
- Auto-create work_item_link: Bug `relates_to` TestCase
- Option to also link to the AC the test case traces_to

**On Bug edit form:**
- Add "Related Test Case" (searchable dropdown from TestCases)
- Add "Affected AC" (searchable dropdown from ACs)
- Add "Affected Widget" (searchable dropdown from widgets)
- Add "Affected Page" (searchable dropdown from pages)

These create work_item_links with type 'relates_to'.

## Technical Notes

- Widgets are app-scoped via `app_id` but FK is nullable for potential cross-app sharing
- `section_order` uses integers with gaps allowed (0, 10, 20) for easy reordering
- Section concept is lightweight - just fields on AC, no separate table
- Steps stored as plain TEXT, UI handles line-splitting and numbering
- Widget reuse tracked by querying `work_items WHERE widget_id = ?`
- All dropdowns should be searchable for large lists
- Status values: new, defined, in_progress, qc, complete

### Key Observations from Sample Data

1. **Widget Reuse:** `stats-cards` and `fixture-card` are highly reusable across other pages (Dashboard, etc.)

2. **Section Types:**
   - Main page content uses `section` type with ordered layout
   - Fixture details uses `tab` type for the tabbed interface
   - Dialogs use `modal` type with NULL section_order

3. **Nested Tabs:** The Analysis tab contains sub-tabs (Statistics, Spider Charts, AI Analysis, Upload Data). These could use `nested-tab` type if further granularity is needed.

4. **Test Coverage:** Test cases link directly to FRs via `parent_id`, enabling traceability from requirement → test → result.
